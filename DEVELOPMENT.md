# Руководство разработчика

## Структура

```
src/main/       main-процесс: окна, безопасность, IPC, сервисы, нативное меню
src/preload/    мост contextBridge (один файл, CommonJS)
src/renderer/   интерфейс на React
src/shared/     типы, схемы, каналы IPC, модель команд и меню, переводы
tests/unit/     Vitest: main и shared (Node), renderer (jsdom)
tests/e2e/      Playwright на собранном приложении
```

Псевдонимы импорта: `@shared/*`, `@renderer/*`.

## Как добавить команду

1. Описать её в `src/shared/menu/commands.ts` (фаза, ускоритель).
2. Добавить в `src/shared/menu/menuModel.ts`.
3. Добавить подпись `commands.<id>` во **все три** файла переводов.
4. Реализовать обработчик в `src/renderer/services/commands.ts`. Пока обработчика нет,
   команда везде неактивна — это намеренно.

Тесты упадут, если команда отсутствует в меню, не имеет перевода или её ускоритель занят.

## Как добавить канал IPC

1. Имя канала — в `src/shared/constants/ipc.ts`.
2. Метод — в `PreloadApi` (`src/shared/types/api.ts`) и в `src/preload/index.ts`.
3. Обработчик — в `src/main/ipc/registerIpc.ts`: обязательно `assertTrusted(event)` и zod-схема для данных.

## PDF.js

- Статические ресурсы PDF.js копируются в `src/renderer/public/pdfjs` скриптом `npm run assets`
  (запускается автоматически перед `dev` и `build`; каталог не хранится в git).
- В юнит-тестах PDF.js подменён (`tests/setup.ts`), движок задаётся через `setPdfLoader`.
  Реальный рендеринг проверяют только сквозные тесты — по пикселям холста.

## Объекты и холст

- Новый тип объекта: тип в `shared/types/objects.ts`, отрисовка в `ObjectView.tsx`, экспорт в
  `drawObjects.ts`, свойства в `PropertiesPanel.tsx`. Экранная и PDF-отрисовка должны строиться
  из одних и тех же чисел.
- Шрифты копируются в `src/renderer/public/fonts` тем же `npm run assets`.
- Жесты мышью проверяют только сквозные тесты; геометрию — юнит-тесты.

## OCR

- Ядро и языковые данные Tesseract копируются в `src/renderer/public/tesseract` тем же `npm run assets`.
- В юнит-тестах движок подменяется через `setOcrEngineFactory`; настоящее распознавание выполняет
  только сквозной тест `tests/e2e/processing.spec.ts` (он заметно дольше остальных).

## Формат проекта

- Схема — `src/shared/schemas/project.ts`. Любое новое поле модели добавляется туда же, иначе оно не
  попадёт в файл: zod отбрасывает неизвестные ключи. Тест кругового чтения
  (`tests/unit/engine/projectArchive.test.ts`) должен включать новое поле.
- Несовместимое изменение формата: увеличить `PROJECT_VERSION` и добавить в `MIGRATIONS` функцию
  перехода с предыдущей версии. Старые версии открываются через всю цепочку миграций.
- В архиве используется только синхронный API fflate (асинхронный несовместим с CSP).
- Копии для восстановления лежат в `<данные приложения>/recovery`. Чтобы проверить восстановление вручную:
  изменить документ, дождаться интервала автосохранения, завершить процесс принудительно, запустить снова.

## Сборка инсталляторов

- `npm run package:mac` и `npm run package:win` собирают приложение и кладут инсталляторы в `dist/`.
  Установщик Windows собирается и на macOS.
- Иконка — `build/icon.png`, рисуется скриптом `npm run icon`; `.icns` и `.ico` electron-builder делает сам.
- Без сертификатов сборка macOS подписывается ad-hoc, сборка Windows не подписывается. Для подписи задайте
  `CSC_LINK`/`CSC_KEY_PASSWORD` (и `APPLE_*` для нотаризации, включив `notarize` в `electron-builder.yml`).
- В упакованном приложении отключены `--inspect` и переменная `PDF_EDITOR_USER_DATA`. Для ручной проверки
  с отдельным профилем используйте ключ Chromium: `"…/PDF Editor" --user-data-dir=/путь/к/профилю файл.pdf`.
- В asar не попадает `node_modules`. Если main-процессу понадобится пакет во время работы, его нужно
  включить в бандл (`externalizeDeps.exclude` в `electron.vite.config.ts`), иначе установленное приложение не запустится.

## Шрифты

- Коммерческие шрифты (Times New Roman, Arial…) в репозиторий и в поставку не добавляются — только чтение установленных в системе.
- Любое место, где текст рисуется или измеряется, берёт семейство через `cssFontFamily`, а начертание — через
  `effectiveVariant`; иначе экран и PDF разойдутся.
- Тесты с реальными системными шрифтами выполняются только на macOS (`it.runIf`); остальные используют DejaVu.

## Правила

- Никакого текста интерфейса в компонентах — только ключи переводов.
- Никаких «кнопок-пустышек»: нет реализации — элемент неактивен.
- Цвета и размеры — только через переменные из `styles/tokens.css`.
- Запись файлов пользователя — только через `writeFileAtomic`.
- Перед завершением задачи: `npm run check` и `npm run test:e2e`.

## Тесты

- Сквозные тесты используют отдельный профиль: переменная `PDF_EDITOR_USER_DATA` задаёт каталог данных.
- Во время e2e на экране на пару секунд появляется окно приложения — это нормально.

## Версии

Зависимости фиксируются точно (`.npmrc`: `save-exact=true`). TypeScript держим на 6.0.x,
пока `typescript-eslint` не поддержит 7.x.
